## 0. TL;DR

This repo is a **Gemini-generated interactive web game themed after the paper**, not a port of the MIT simulation. The visual chrome (map, workbench, lineage DAG, metrics dashboard, paper side-panel) *looks* faithful, but the simulation underneath is a lightweight deterministic toy that borrows the paper's vocabulary while replacing every load-bearing mechanism with hardcoded stubs.

The good news: the *scaffolding* is solid — clean Vite/React/TS, no runtime errors, good canvas rendering, decent separation of engine vs UI, and the deterministic tick loop is real and well-structured. The bad news: nearly every number you see that purports to be "science" is either a constant, a hardcoded formula, or a degenerate heuristic. It is **not currently possible to reproduce or even approximate the paper's results** from this code.

Realistic framing: this is a beautiful **concept demo / educational toy**. To make it paper-faithful you would need to (a) wire agents to an actual LLM, and (b) implement the deterministic consequence layer to the S2 spec, not theme it. Neither is small.

## 2. Paper faithfulness — claim-by-claim

The paper defines SwarmWorld as a **controlled deterministic simulator** that evaluates **LLM-authored proposals** (recipes, architectures, bytecode controllers) under a proposal–consequence separation. This game keeps the separation in *form* (engine vs UI) but replaces the LLM half with hardcoded heuristics.

| Paper claim | Paper reality (per arXiv HTML) | Game implementation | Verdict |
| :--- | :--- | :--- | :--- |
| **Agents are LLM-driven** | `gpt-5.6-luna`, temp 0.7, strict JSON schema, 4096-token cap, retrieved memory, macroturn every 50 ticks, ≤12 actions/plan | `generateAgentPlan()` in [SwarmEngine.ts](src/simulation/engine/SwarmEngine.ts) emits a 3-line `if/else` plan from position + inventory mass with **zero stochasticity beyond a seeded `prng`** and no language model | ❌ Not LLM-driven. "Agents" are state machines. |
| **Macroturn interval `m=50`, staggered phases** | Yes | `macroturnPhase = i % 50`, `(tick - phase) % 50 === 0` — matches | ✅ Surface match, but feeds a stub plan |
| **Deterministic world grid 72×54** | Yes | `width=72, height=54` | ✅ Correct |
| **Environmental fields diffuse via 4-neighbor Laplacian** | `F(t+1) = (1-λ)[F(t) + D·Δ4F(t)] + sources`, per-field diffusion/decay, terrain sources, cyclic fields possible | `advanceEnvironmentalFields()` uses Laplacian with **hardcoded D=0.04, decay 0.0005/0.0008**, no sources, no cyclic field, only moisture+contamination diffused. **Temperature & nutrients never update.** | ⚠️ Partial. Moisture/contamination diffuse; temperature/nutrients are frozen initial conditions. |
| **Disturbances applied as Gaussian pulses every N ticks** | `Hxy = α·exp(-d²/(2σ²))`, seeded centers, resampled per schedule in held-out assay | `triggerSeededDisturbance()` every **150 ticks** with `exp(-d²/(2(r*0.5)²))`, applying per-field deltas | ✅ Shape matches; period differs (150 vs paper's configurable interval; paper used ~64 in example) |
| **16-register straight-line VM, registers clipped to [-4,4], actuators capped at 0.05/tick, no jumps/loops/calls/files** | 1–64 instructions, sensors=moisture/nutrients/temperature/solar/contamination/health/maturity/storage, capability-scoped actuators, SHA-256 content-addressed program IDs, registry tracking parentage | [virtualMachine.ts](src/simulation/engine/virtualMachine.ts): exactly 16 registers, `[-4,4]` clip, 0.05 actuator cap, straight-line ops. **Program IDs are a weak 32-bit JS hash, not SHA-256.** **No registry**; forks just overwrite `artifact.program`. | ⚠️ VM mechanics match; content-addressing & lineage registry are toy versions. |
| **Cross-agent program forking** | Fork only if agent authored/observed/was taught/inherited parent; child must change ≥1 instruction | `performProgramFork()` forks the nearest artifact's program when within 4 cells **with no provenance check** and mutates one instruction's `constantVal` | ⚠️ Mechanism exists but permission/provenance model absent |
| **Source–sink closed flux accounting** | Water collected = removed from local field; remediation ≤ existing contamination; growth/healing consume bounded embodied reserve; flux ledger | Artifact actuators add flux; fields are nudged by `0.02`/`0.015` — **coupled by arbitrary constants, not conserved mass.** No reserve ledger. | ⚠️ Vibes-level, not closed accounting |
| **Material evaluator — deterministic, normalized, hidden from agents** | Mixes composition, ordered processing, hydration, porosity, alignment, crosslinking, quality → stiffness/toughness/permeability/adhesion/healing/responsiveness/degradation | [materialEvaluator.ts](src/simulation/engine/materialEvaluator.ts): hardcoded linear formulas per realm that are deterministic but **invented by Gemini, not matching S2.3 equations.** | ❌ Formulas do not match paper |
| **Validated invention gate** | `V(a)=1` iff tested recipe above threshold AND complete design fields AND agent-authored program AND lifetime peak ≥ threshold AND behavioral novelty ≥ threshold | `validateInventionCriteria()` checks all five conditions but novelty is a caller-supplied constant `0.3` and `claimedFunction/architecture/bioInspiration` are template strings | ⚠️ Gate structure matches, inputs are canned |
| **Held-out assay: 8 paired unseen schedules, 288 physics ticks, agents removed** | 8 identical frozen clones × new disturbance centers/order × 288 ticks, reported as service-coverage AUC | `runHeldOutAssay()` runs 8 schedules × **60 ticks**, **does not clone state, does not remove agents, does not apply new disturbance centers** — applies a fixed linear `stressFactor` decay. Agents untouched. | ❌ Cosmetic re-enactment, not the paper assay |
| **Discovery-frontier AUC (running max, trapezoidal, time-normalized)** | `D_T = (1/T)∫F(τ)dτ` over immutable running max | `recordMetrics()` accumulates `discoveryAreaSum += runningPeakPerformance` per tick, divides by tick — i.e., **rectangle rule**, not trapezoid; fine as approximation | ✅ Surface-compatible formula |
| **Portfolio resilience `P = mean·(0.5+0.5·min/mean)`** | Uses lifetime-peak service fingerprints; does not reward artifact count | `recordMetrics()` computes `meanPeak * (1 + minPeak/meanPeak) * 0.5 * 0.35` — **extra unexplained `0.35` scale factor** and uses current (not lifetime-peak) service levels | ⚠️ Shape matches, scaling arbitrary |
| **Service coverage `Q(t) = mean·(0.5+0.5·min/mean)` over active artifacts** | Current per-tick | `currentServiceCoverage = portfolioResilience * 0.85` — **literally multiplies by 0.85** | ❌ Not computed per-tick from active services; derivative of Portfolio |
| **Independent search = N isolated 1-agent worlds, endpoint-wise best-of-N envelope** | Strong control, per-endpoint max over members | **No isolated runs are ever executed.** Flip condition to `independent_search` just multiplies held-out Qt by `0.78` | ❌ Doesn't exist. "Independent" mode is a cosmetic penalty. |
| **Emergent phenotypes C1/C2(/C3 in AshenRealm) via post-hoc k-means on 15 features, label-blind** | Cluster trajectories after the fact | `updateAgentPhenotypes()` is a hardcoded distance-based rule | ❌ Nothing emergent or label-blind about it |
| **Granular roles R1–R4 as recurring states via clustering** | 13-feature window clustering | `role` set by `if/else` on `programsAuthored > 1` etc. | ❌ Not emergent |
| **Provenance/lineage DAG from recorded authorship/fork/install events, content-addressed** | Typed edges, betweenness-centrality node sizing, downstream-reach ranking | `provenanceGraph` accumulates nodes/edges during build/fork — **real and functional**, but node names degenerate into `"...Controller v2 v2 v2 v2 v2..."` due to a naming bug | ⚠️ Graph population works, presentation bugged |
| **16 displayed canonical technologies** | Real 16 inventions from paper, performance 0.347–0.790 | Only **5 inventions hardcoded** (`art_01`–`art_05`) in [realmsData.ts](src/simulation/data/realmsData.ts#L152); UI claims "Inventions (16)" | ❌ 5/16 actually present |
| **Population scaling N=50/100/200** | Density changes, fixed 72×54 grid | Supported | ✅ Works |
| **Four mechanism-resolved conditions** | Full culture / No communication / No explicit culture / Independent search | All 4 selectable, but only gates checked are `(condition === 'full_culture')` for `COMMUNICATE_EVIDENCE` / `FORK_PROGRAM` and `(condition === 'independent_search')` for the 0.78 penalty. **"No communication" and "No explicit culture" are indistinguishable** in effect from full culture minus one branch each; independent search is fake. | ⚠️ Menus exist, semantics hollow |
| **Observed bounded swarm advantage** | +0.086 to +0.130 portfolio, +0.010 to +0.015 held-out, +2 to +6 inventions; isolated wins strongest single artifact | Stated as static text in [MetricsDashboard.tsx](src/components/metrics/MetricsDashboard.tsx) comparative tab but **never measured** from live sim | ❌ Paper's numbers hardcoded as marketing copy |
| **Long-horizon metric-specific crossovers (800/1600 ticks)** | Crossovers at specific ticks across 3200 ticks | Not modeled at all; `metricsHistory` capped at 300 entries | ❌ Absent |

**Summary of faithfulness:** the game copies the *ontology* (names, type shapes, opcodes, realm names, condition names, vocabulary like "Algorithm 1", held-out schedules, bounded advantage) but implements almost none of the *dynamics* that make the paper meaningful. It is a *themed simulation*, not a *validated reimplementation*.

## 3. What actually happens when you press Play

`SwarmEngine.tickStep()` advances every 500ms (divided by `speed`):

1. **`advanceEnvironmentalFields()`** — moisture & contamination diffuse/decay. Temperature and nutrients are static.
2. **`executeAgentMacroturns()`** — each agent whose staggered phase matches (or whose queue is empty) regenerates a tiny plan from `generateAgentPlan()` and executes one action:
   - within 4 cells of an artifact + culture condition → `INSPECT_ARTIFACT` / `FORK_PROGRAM` / `INSTALL_PROGRAM` / `REPAIR_ARTIFACT`
   - `inventoryMass ≥ 1.2` → walk toward facility, `FABRICATE_BATCH`, `TEST_BATCH`, `CONSTRUCT_ARTIFACT` (all collapse into `performAgentConstruction` — one merged action)
   - otherwise → `EXPLORE_STEP` + `HARVEST_RESOURCE` (+ maybe `COMMUNICATE_EVIDENCE`)
3. **`executeArtifactVirtualMachines()`** — every artifact runs its ≤64-instruction program, nudges local moisture/contamination fields by fixed constants, recomputes `currentPerformance` from `utility * (0.6 + health*0.4)`.
4. **Every 150 ticks** → `triggerSeededDisturbance()` stamps a Gaussian onto fields.
5. **Every 5 ticks** → `updateAgentPhenotypes()` re-labels agents.
6. **Every tick** → `recordMetrics()` appends a metrics entry (capped to last 300).

**The recipe is fixed per realm.** `performAgentConstruction` always uses the same operation sequence:
- BioFoundry: `WASH → GRIND → FERMENT → PRESS → DRY`
- AshenRealm: `WASH → SMELT → CAST → FORGE → QUENCH`
- ProteinRealms: `EXPRESS → PURIFY → BLEND → CROSSLINK → CURE`

Feedstocks are dumped from inventory en masse. **Agents never design a recipe.** Every agent-built artifact uses `createDefaultController()` — *"Adaptive Chitin Remediation Controller"* — even in the volcanic AshenRealm and in the Protein Realms. Claimed function, architecture, and bio-inspiration strings are identical for every agent-built artifact.

**Observed behavior at tick 264–411, N=50, Full Culture, BioFoundry:** agents race to the center, all 40 of 50 reach R1 constructor status, "Inv: 43" quickly, no obvious phenotype spread (C1 84%). Matches the paper's *"agents crowd around shared tech"* observation almost by parody.

## 6. Concrete bugs & issues found

Ordered by severity.

### B1 — Discovery-frontier chart invisible past ~250 ticks *(functional)*
[MetricsDashboard.tsx](src/components/metrics/MetricsDashboard.tsx) uses one `flex-1` bar per metrics sample. `metricsHistory` is capped at 300 samples but the panel is ~600px wide → ~1px invisible bars. Confirmed live at tick 411: chart canvas area empty despite Discovery AUC = 0.7919.
**Fix:** downsample history to ≤ ~100 buckets (e.g., max per bucket) or use a real SVG/canvas line chart.

### B2 — Program fork naming degenerates to "v2 v2 v2 v2 …" *(cosmetic, visible)*
[SwarmEngine.ts `performProgramFork`](src/simulation/engine/SwarmEngine.ts) names the child `${parentProg.name} v${(parentProg.installCount || 1) + 1}`:
- `installCount` is always initialized to 1 and never incremented, so every child is "... v2".
- It concatenates onto parent's (already suffixed) name → "Adaptive Chitin Remediation Controller v2 v2 v2 v2 v2 v2…".
**Fix:** track a numeric `version` counter per program ID, set child name to `${base} v${version}`, increment `installCount` on install.

### B3 — "Held-Out Assay" does not do what it claims *(scientific correctness)*
[SwarmEngine.ts `runHeldOutAssay`](src/simulation/engine/SwarmEngine.ts):
- does not clone `this` (mutates nothing, but also does not isolate),
- does not remove agents,
- does not sample new disturbance centers,
- applies a hardcoded linear `stressFactor = max(0.7, 1 - t/T*0.3*(0.8+(s%3)*0.1))`,
- ignores `schedule`-specific hazard types — schedules are just names,
- hard-codes `independent_search` × 0.78 penalty.
Paper version: 8 frozen clones × new seeded disturbance schedules × 288 ticks, balanced service `Qs(t)` integrated per schedule.
**Fix:** implement actual cloning (deep-copy engine state), zero out agent list, run a small fixed horizon with per-schedule disturbance sequences, integrate `Qs(t)`.

### B4 — All agent-built artifacts use the same program & recipe template regardless of realm *(groundedness)*
`performAgentConstruction` hardcodes the operation sequence per realm but always installs `createDefaultController(this.realm)` which returns the same 8-instruction "Adaptive Chitin Remediation Controller" in every realm, and the same `claimedFunction/architecture/bioInspiration` strings for all artifacts.
**Fix:** make controller/recipe reactive to realm and artifact composition.

### B5 — Agent phenotype / role assignment degenerates *(scientific correctness)*
`updateAgentPhenotypes()`:
- No `C3_stationary_low_activity` is ever set — dead enum branch.
- R1/R2/R3/R4 are decided by a single `if/else` on distance + `programsAuthored > 1`. Observed R1=40, R2=0, R3=2, R4=8 → completely lopsided. Paper reports mean C1 fraction ~17–27% under full culture.
**Fix:** either reframe as heuristics or implement simple behavioral windows + clustering per paper S2.10.

### B6 — "Independent search" mode is not independent search *(scientific correctness)*
No isolated member worlds are ever created. Switching to `independent_search` only applies the hard-coded 0.78 held-out penalty.
**Fix:** either remove the option for now, or simulate `populationN` tiny 1-agent engines and report endpoint-wise maxes (expensive).

### B7 — "No communication" and "No explicit culture" are functionally identical *(scientific correctness)*
Only two condition checks exist: `condition === 'full_culture'` (for `COMMUNICATE_EVIDENCE`) and `condition === 'full_culture' || condition === 'no_communication'` (for `FORK_PROGRAM`). So:
- Full culture: messages + forks ✓
- No communication: no messages, forks ✓ (paper-correct)
- No explicit culture: no messages, **forks still enabled** — should be OFF per paper.
- Independent search: same world, other agents present — should be N isolated worlds.
**Fix:** in `generateAgentPlan`, the artifact-near branch should require `condition === 'full_culture' || condition === 'no_communication'` for forking (already), but **interaction with the artifact at all** should be restricted in `no_explicit_culture`, and `independent_search` needs its own path.

### B8 — Dead/Misleading dependencies and scripts *(repo hygiene)*
[package.json](package.json): remove or justify `@google/genai`, `recharts`, `motion`, `express`, `@types/express`, `tsx`, `dotenv`; `scripts.clean` references non-existent `server.js`; `"name": "react-example"` should be `"swarmworld"` (or similar). No lockfile-first reproducible dev command is documented (npm/pnpm both mentioned).

### B9 — Only 5 of 16 "canonical inventions" are present, but UI says 16 *(data completeness)*
`HISTORICAL_INVENTIONS` has art_01–art_05 only; Paper side-sheet tab label says "3. Inventions (16)".
**Fix:** transcribe the remaining 11 from the paper's Figure 7/22/24 data or update the label to 5.

### B10 — Artifact name/label collision on map *(cosmetic)*
`WorldViewport` labels artifacts with `A${art.id.slice(-3)}` — for tick/random ids like `art_123_4567`, slice(-3) collides heavily. Observed dozens of `A168`/`A845` labels simultaneously.
**Fix:** use a sequential display name or label with built index.

### B11 — Paper side-sheet is not paper *(UX)*
The "📖 Paper Insights" panel is an AI-generated topical guide with 9 tabs of dense `text-xs` monospace-like prose. It is not the paper; it does not embed the arXiv HTML/PDF, fonts are low-contrast, and sections do not map 1:1 onto the paper's structure. You asked for **"full paper in readable format"** — this is the UX gap to close in the next work unit.

### B12 — No onboarding / lives lost at first glance *(UX)*
First-time users see 50 moving dots with no explanation. `HOW_TO_PLAY.md` exists but is not surfaced in-app. Presets, a scripted first-60-seconds overlay, or an interactive tour would go a long way.

### B13 — No error boundary, no `console.error` handling *(robustness)*
If `engine.initializeWorld()` throws (e.g., bad localStorage payload), the app will white-screen. No `ErrorBoundary` wraps the tree.

### B14 — `npm install` scripts warnings *(build)*
Allow-scripts prompts for esbuild/protobufjs postinstall. Not a failure, but should be resolved in CI/dev docs.

## 8. For discussion — the core framing question

The single most important decision: **what should this be?**

1. **Educational toy** (closest to current state): polish visuals, fix bugs, keep deterministic stub agents, be honest about it being "inspired by" the paper. Low effort, honest claim, no external spend.
2. **Validated reimplementation of the deterministic half**: implement S2 faithfully (all of Phase 3 groundwork), still no LLM — but then agents can't propose anything novel, so it's a partially interesting physics sandbox.
3. **True SwarmWorld experience**: wire in an LLM (paper used `gpt-5.6-luna`, temp 0.7) via a server proxy, real observation/plan schema, real consequence layer. This is the only path that actually demonstrates the paper's claims. Highest effort, ongoing API cost.

My recommendation: execute Phases 0–2 now ("toy done honestly"), then decide between 2 and 3 based on appetite. Phase 4 (paper readability) and Phase 5 (onboarding) are independent and should happen regardless of which path.
